# Chapter 97 — Interaction Philosophy

Interaction is communication.

Every gesture,
animation,
transition,
tap,
swipe,
long press,
or vibration
must communicate meaning.

Interaction should never exist purely because it looks impressive.

Every interaction must answer one of three questions.

• What happened?
• What changed?
• What should happen next?

If an interaction cannot answer one of those questions,

it should not exist.

---

## Interaction Goals

Ledger interactions should feel

Predictable

Calm

Precise

Responsive

Forgiving

Trustworthy

Users should develop muscle memory.

Never surprise users with changing behaviors.

# Chapter 99 — Navigation Behavior

Navigation communicates hierarchy.

Primary navigation

Instant.

Secondary navigation

Animated.

Contextual navigation

Shared element.

Destructive navigation

Requires confirmation.

Deep navigation should never exceed four levels.

Users should always know how to return.

# Chapter 101 — Motion Language

Motion exists to preserve continuity.

Nothing should appear unexpectedly.

Every animation should preserve object permanence.

Users should always understand

where an element came from

and

where it went.

# Chapter 102 — Animation Rules

Animations should never delay work.

Animations should never block interaction.

Animations should never become performance bottlenecks.

Animation duration

Micro

100ms

Small

150–200ms

Normal

250–300ms

Large

350–450ms

Never exceed 500ms during normal navigation.

Not excitement.

Selection

Medium

Confirmation

Heavy

Critical Warning

Double

Major Achievement

Never vibrate for ordinary scrolling.

Never vibrate for decorative reasons.

# Chapter 105 — Confirmation Philosophy

Not every action requires confirmation.

Confirm only when

Irreversible

Financially meaningful

Privacy affecting

Security affecting

Examples

Delete Account

Reset Learning

Disconnect Institution

Erase History

Never ask

"Are you sure?"

for routine navigation.

# Chapter 113 — Behavioral Consistency

Users should never ask

"What happens if I press this?"

Behavior should remain identical throughout the application.

If one card expands vertically,

every equivalent card expands vertically.

If one swipe accepts,

every equivalent swipe accepts.

Consistency reduces learning.
